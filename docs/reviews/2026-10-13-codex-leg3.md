## Change

1. **Integrate before you add.** Nine `checkpoint-*` modules, the owned facade and the index publication exist, but no
   running signer uses them.
   - Build one vertical slice first: a `solanaut-signer` process.
     - It loads a protected devnet key and takes proposals on its socket.
     - It decides through the guard, then signs, sends and follows up.
     - It restores after a kill.
   - Add a component only when the next commit wires it in.
2. **Keep evidence in proportion.** A receipt needs:
   - the command, the revision and the date;
   - the counts;
   - the excerpts that show the failure and then the pass;
   - a SHA-256 of any raw output.

   From now on:
   - commit no more than 100 KB of raw output per receipt. Keep the rest under `.sandbox/evidence/`, named in the
     receipt by its hash, or commit it gzipped when it truly must be kept;
   - never copy hosted CI logs into the repository; cite the run ID;
   - leave the evidence already committed as it is.
3. **Stop the work that publication made moot.** The human published this repository on 2026-10-12 with a rewritten
   history.
   - H15, PUB-1's history inventories and the history-byte reviews are closed.
   - SBOMs, schema validation and reproducible builds belong to the freeze (mission phase 6), not now.
   - The list of changed assertions (§8) is one table, kept current. No more receipts about it.
4. **Lead with the blocker.** H11 held back the D41 and D42 fixes and kept CI red for days. Yet it read as one entry
   among dozens.
   - When one decision blocks the work, put it first in §5, in one sentence that says what waiting costs.
   - Say it again in the session's last message to the human.
   - Meanwhile, do the next item that is not blocked. 3.3's decoding and classification need only the SDK.
5. **Write for people.** `PROGRESS.md` is public, and judges read it. A line like "S150's earlier frozen map does not yet
   index this receipt" tells them nothing. For each session:
   - `PROGRESS.md` gets at most five lines: what works now that did not, what broke, what is blocked;
   - `docs/HANDOFF.md` §7 gets at most ten lines, and the details go in the run record and the receipts;
   - an S-, D-, O- or H-number appears only beside a plain description of it.
6. **CI is part of the product now.** Every push publishes, and a red mark is the first thing a visitor sees.
   - A green `main` comes before new work.
   - Today the three runtime test jobs never finish. `npm test` fails on H11, then the installed-package fault
     injections run past the 10-minute limit.
7. **Drop the rituals.** A verified bundle and a full `git fsck` for every checkpoint, and commits deliberately left
   unpushed, cost time and protect nothing a push does not. The standing grant is back: commit and push `main` after
   each green step.

## The human's new point: ADR-025

While answering, the human raised a point. A refusal's reason should go to a separate interface the user sees,
outside the agent's pipeline. An agent that knows why it was refused will try to correct the request or get around
the rule, because its harness pushes it to make the transaction succeed however it can.

Today the agent is told the rule that fired and, for the caps, the limit itself and how much of
the window is used. Claude drafted
`design/ADR-025-denial-disclosure.md`, and the human accepted it:
- the agent hears only `refused`, `retry-later` or `invalid`, with a reference number;
- the operator gets the full reason, through the record, the cockpit and an `onRefusal` callback;
- a signed `"full"` setting shows reasons to the agent during development only.

It comes before the signer's socket replies, so that protocol is built once.
