# Solanaut 1.0 — implementation mission

Approved by the human in this session on 2026-10-05. This is an implementation queue,
not evidence of achieved readiness. Baseline: `e925f1d`, the approved Beta.

## Release contract

- Stable individual deployment on Linux, local or VPS, on devnet first.
- Dedicated signer user, protected devnet key file, Unix socket and localhost dashboard.
- Ubuntu 24.04 x86-64 is the initial reference deployment; support claims require its evidence.
- Native TypeScript development; a release-only JavaScript and declaration build for npm.
- The original repository becomes public only after history/content review and human approval.
- Every existing audit, bounty, independent evaluation, usability and readiness gate remains.
- Mainnet is a separate future qualification; this mission authorises no real-funds operation.

## Contracts that need explicit design

Persist request payload binding and lifecycle evidence before sending; unknown sends retain their
reservation and are reconciled without client resends. Signing-only SDK APIs remain distinct from
the isolated sending path. Require durable isolated-mode state and atomic single-writer ownership.
Version rules, policy and records; snapshots rebuild Keel through replay. Upgrades preserve live
attempts, receipts and latch; policy versions only rise, including when reverting policy content.

RPC failover cannot release reservations on stale or conflicting evidence. Opaque execution stays
denied until intervening-deposit and destination semantics are proven. Anchor guarantees distinguish
successful anchors from target cadence/outages. Operator cap exceptions bind exact bytes and expiry
while retaining all non-cap rules. Changes beyond accepted ADRs remain proposals for the human.

## Validation and ownership

`docs/READINESS.md` remains the threshold authority. Each requirement has positive, negative,
boundary and adversarial tests; retain initial failure and planted-fault output. Freeze definitions
before results and use fresh seeds after definition changes. Preserve historical independent reports;
maintained regressions follow their triage, not superseded expectations.

Outside developers' Alpha integration study precedes the Alpha exit; final usability is a separate
Leg 5 gate. Local-validator and devnet soak results are labelled by environment. Crash tests do not
prove power-loss durability; request idempotency does not prove exactly-once chain execution.

Publication, licence, OS users, tool approvals, Phantom actions, audit/bounty commitments and
submission remain human-owned. Protected gate/harness edits are exact owed edits, never direct
changes by Codex. Private commits follow tests/typecheck/close gates and coherent receipts.

The hackathon pitch shows achieved milestones at submission time, without replacing release gates.
