# p-token: three instructions added to the Token program

Read at milestone 2a.3, to check whether the Token program's instruction list had grown since the classifier's list
was written.

## Key facts

- It replaces the Token program's implementation with p-token, keeping "the same instructions and account layout".
- It adds three instructions: `withdraw_excess_lamports` (discriminator `38`, the value SPL Token-2022 already uses),
  `batch` (`255`), which "can execute a variable number of" token instructions in one, and `unwrap_lamports` (`45`).
- The proposal's status field reads "Review".
- `@solana-program/token` 0.17.0 identifies all three.

## What it supports

- `packages/sdk/src/classify.ts`: all three are denied by not being on the allowlist. `batch` matters most: it could
  carry a transfer the guard would not see.
- `docs/SPEC.md` §4, the SPL Token row.

## Caveats

- Whether p-token is active on mainnet was not checked here; the allowlist denies the three either way.
