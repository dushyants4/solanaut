## Found

- **Squads v4 holds on devnet** exactly as rehearsed. Each refusal is the program's own, recorded with a signature.
- **Scene 5 latches the guard on every run.** One re-sign while the first attempt is in flight meets REGROUND. This is
  the open question in `docs/SPEC.md` §12, now with a well-behaved agent on devnet. To decide before the demo is
  recorded.
- **The loop stops at turn 2 after earlier denials,** not at turn 3: recent denials count against valence.
- **Solana Agent Kit 2.0.10 tells the agent a landed payment failed** on devnet, because its `sendTx` re-sends until it
  sees a status (M13). That invites a retry, which is how D14 was found: behind a sign-only integration the guard
  could admit that retry after expiry.
- **What got in the way, at the same size:**
  - **The public devnet RPC rate-limits per method.** It stopped the first drill, and it would have stopped
    `guardedWallet` at every height read. Now both ride it out.
  - **The boundary guard denied two commands** whose text named a key path or `cache.keys()` beside a file write. It
    failed closed as designed, and the edits went through script files.
  - **A local validator's slow status read** inflated a revoke time fourfold. The slot count is now recorded beside
    it.
