# The byte decoder: shown failing, then passing

Milestone 2a.2 in [docs/ROADMAP.md](../../docs/ROADMAP.md): legacy, v0 with pinned tables, and v1 read from bytes
alone, as [docs/SPEC.md](../../docs/SPEC.md) §4 specifies. Run on 2026-09-30 with Node 26.7.0, `@solana/kit` 8.4.0
and `@solana/web3.js` 1.99.0.

| File | What it is |
|---|---|
| `packages/sdk/src/message.ts` | `decodeMessage`, `resolveMessage` (v0 tables from pins only) and `decodeTransaction` (wire bytes to message and signatures) |
| `packages/sdk/src/base58.ts` | the address codec, so the decoder needs no library |
| `packages/sdk/src/tables.ts`, `packages/sdk/bin/pin-table.ts` | a lookup table account's bytes to a pin, and `npm run pin-table -- --url <rpc> <table>` |
| `packages/sdk/test/decode.test.ts`, `pin-table.test.ts` | 26 tests |
| `packages/sdk/test/support/kit.ts`, `craft.ts` | the reference messages: generated by kit from seeds, and hand-built bytes for shapes no encoder emits |

**Not one import of `@solana/web3.js` or `@solana/kit` in `packages/sdk/src/message.ts`, `base58.ts` or `tables.ts`.**
Kit is a dev dependency; it is the reference the tests check against.

"Decode to effects", in the milestone's wording, is read here as: decode to the message and every instruction's
resolved accounts. Effects, meaning what moves and to whom, are the classifier's job at milestone 2a.3.

## 1. Failing first

The 24 decoder tests were written against a stub whose every function threw `not implemented`. The typecheck was
clean, so the tests compiled against the real interface.

```
ℹ tests 24
ℹ pass 0
ℹ fail 24
```

## 3. Would the tests notice a bug? Five planted, five caught

Each bug was planted alone in the passing decoder, the decoder battery run, and the file restored.

| Planted bug | Failing tests | First to fail |
|---|---|---|
| a static account's writability off by one | 2 | golden set: accounts resolve as kit resolves them |
| v1 config values read out of mask order | 3 | golden set: 300 messages decode as kit decodes them |
| non-canonical compact lengths accepted | 1 | a non-canonical compact length is malformed |
| the fee payer allowed as a program | 1 | an instruction may not name the fee payer as its program |
| base58 drops a leading zero byte | 6 | base58 agrees with kit's address codec |

The pin command was written before its two tests, so it got the same treatment: reading at `confirmed` instead of
`finalized` commitment, and removing the owner check. Each was caught by one test.

## 4. The fuzz harness, run harder

The harness mutates kit-built messages of every version: bit flips, set bytes, insertions, deletions, truncations,
splices from another message, and pure noise. Each input must either decode exactly as kit decodes it, or be refused
with a `DecodeError` naming its rule. Any other exception fails the run.

```
FUZZ_SEED=1 FUZZ_RUNS=100000   18,758 accepted and matched kit, 81,242 refused with a named rule
FUZZ_SEED=2 FUZZ_RUNS=100000   18,754 accepted and matched kit, 81,246 refused with a named rule
FUZZ_SEED=3 FUZZ_RUNS=100000   18,820 accepted and matched kit, 81,180 refused with a named rule
```

That is 300,000 inputs with no disagreement. The differential runs one way only. The decoder is deliberately stricter
than kit: it refuses trailing bytes, non-canonical lengths, unknown v1 config bits, inconsistent headers, duplicate
accounts, a lookup table listed twice, and messages too large to land. Kit decodes all of these.

## 5. The toolchain doctor's v1 validator check

`tools/doctor.py` now checks the validator that runs v1 transactions, by its absolute path, at 4.2.2 or later. It was
pointed first at the inactive 3.1.10 release:

```

```

Then at 4.3.0:

```

  all 13 tools match
```
